Q1. Datasheet와 Reference Manual(RM)의 차이가 무엇인가요? 각각 언제 보나요?
면접관의 속마음: "이 친구가 하드웨어 스펙과 펌웨어 레지스터 문서를 구분할 줄 아는가? 아니면 그냥 닥치는 대로 구글링하나?"
• Datasheet (하드웨어/회로 설계용): 칩의 전기적 한계($V_{DD}$, 최대 허용 전류 $I_{max}$), 핀 배치도(Pinout), 5V 내압 허용(FT 마크) 여부, 패키지 치수를 확인할 때 봅니다. 즉, "보드가 타지 않도록 회로를 설계할 때 보는 책"입니다.
• Reference Manual (펌웨어/소프트웨어 제어용): 메모리 맵, 각 주변장치(GPIO, Timer, ADC)의 내부 레지스터 오프셋과 비트 필드 설명서입니다. 즉, "C 언어로 코딩할 때 레지스터를 조작하기 위해 보는 책"입니다.
Q2. 처음 보는 센서나 타이머를 제어하라고 하면, 1,700쪽 매뉴얼을 어떤 순서로 보시나요?
면접관의 속마음: "두꺼운 문서를 만났을 때 길을 잃지 않는 자기만의 체계적인 내비게이션 공식이 있는가?"
"저는 3단계 공식으로 독해합니다. 첫째, Memory Mapping 장에서 그 장치가 연결된 버스(AHB/APB)와 Base Address를 찾습니다. 둘째, 해당 장치 챕터 끝의 Register Map 표로 바로 건너뛰어 사용할 레지스터들의 Offset 목록을 확보합니다. 셋째, 세부 비트 설명 장에서 비트 필드 설정값을 확인하고 즉시 C 언어 구조체 포인터로 직결합니다."
Q3. 레지스터 맵(Table 23)에서 'Reset Value'가 왜 그렇게 중요한가요?
면접관의 속마음: "디버그 핀을 날려먹거나 칩을 벽돌(Bricking)로 만들어 본 실무 실패 경험이 있는가?"
"전원 인가 직후 하드웨어의 안전 상태를 의미하기 때문입니다. 대표적으로 GPIOA_MODER의 리셋값은 0이 아니라 0xA8000000입니다. 상위 3개 핀(PA15, PA14, PA13)이 SWD/JTAG 디버그용 Alternate Function으로 보호되어 있기 때문입니다. 이를 모르고 레지스터를 = 0x01처럼 통째로 덮어쓰면 ST-LINK 통신이 즉시 끊겨 칩이 벽돌이 됩니다."
Q4. 비트마스킹(Read-Modify-Write)을 하지 않고 대입 연산자(=)를 쓰면 어떤 사고가 터지나요?
면접관의 속마음: "전력전자 모터 제어나 임베디드 실무에서 원자성(Atomicity)과 부수효과(Side Effect)의 위험성을 아는가?"
"내가 조작하려던 1개 핀 외에 나머지 15개 핀의 설정이 강제로 0으로 리셋됩니다. 모터 제어 인버터의 경우, 멀쩡히 돌던 게이트 드라이버 핀의 모드가 바뀌면서 상·하단 MOSFET이 동시에 켜져 전원-접지가 단락(Shoot-Through)되어 소자가 폭발할 수 있습니다. 그래서 반드시 &= ~로 해당 비트만 비우고 |=로 해당 비트만 채우는 RMW가 철칙입니다."

🏢 대형 아파트 단지 비유로 보는 3단계 하드웨어 계층 구조

"물리 핀 밑에 레지스터가 있는 게 아닙니다. 아파트 관리실 제어판(레지스터) 1개 밑으로 16개 세대의 창문(물리 핀)이 연결되어 있습니다."

1. 아파트 단지 = GPIOA

• 물리적 실체: STM32 칩 내부의 독립적인 1KB 하드웨어 페리페럴 블록.
• 주소: 0x4002 0000 (Base Address)
• Port A와 GPIOA: 100% 동일한 대상을 부르는 이름입니다.

2. 통합 배전반 = MODER 레지스터

• 물리적 실체: 1층 관리실에 놓인 단 1개의 32비트 하드웨어 래치(플립플롭).
• 주소 오프셋: + 0x00
• 구조: 32칸짜리 스위치 패널이 2칸씩 16등분되어 각 세대를 통제합니다.

3. 세대 창문 = 물리 핀 (PA0~PA15)

• 물리적 실체: 칩 외각으로 돌출된 금속 다리 (IC Pin Pad).
• 1:1 매핑: n번 세대 창문은 MODER 제어판의 n번째 2칸 스위치([2n+1:2n])에 직결되어 열리고 닫힙니다.
