PART 02 / 읽고 쓰기

핀의 안팎을
연결합니다.

스위치 전압을 읽어 LED 명령으로 바꾸고, 핀 안의 출력단이 어떻게 그 명령을 수행하는지 살펴봅니다. 마지막에는 C 코드와 레지스터 주소를 연결합니다.

기초·중급 · 약 15–30분강의 74–77 기반

이 페이지는 초기 강의의 PD3 LED·PD4 버튼 회로를 사용합니다. 개정 보드의 PC6 적용은 9단원 보드 개정 디버깅을 확인하세요.

04 / 전압 → IDR → 조건문 → ODR

스위치를 놓았을 때, 누가 HIGH를 만들까요?

IDR(Input Data Register)은 핀의 입력 논리값을 읽는 레지스터입니다. PD4 입력은 IDR bit 4에서 읽습니다. 스위치를 누르면 PD4가 접지와 연결되어 LOW가 되고, 놓으면 외부 풀업(pull-up) 저항 R4가 전원 쪽으로 핀 전압을 끌어올립니다. 풀다운은 반대로 접지 쪽에 저항을 연결합니다.

원래 보드에는 R4 1kΩ 외부 풀업과 C6 100nF 콘덴서가 있습니다. 내부 풀업을 끄더라도 R4가 남아 있으므로 놓인 입력이 곧바로 뜨지 않습니다. 어디에도 전압이 정해지지 않는 상태를 부동(floating)이라고 합니다. 아래에서는 외부 풀업까지 제거하는 가상 비교로만 부동을 만듭니다.

EXPERIMENT 04원회로 / 가상 비교

해 보기: ① 버튼을 누르고 놓기 → ② 내부 풀업을 바꾸기 → ③ 놓은 상태에서 외부 R4도 제거하기. 예상 관찰: R4가 있으면 내부 풀 없음에서도 HIGH, 두 풀업이 모두 없으면 미정입니다.

전제: Port D 클럭 ON, PD4 입력 모드, PD3 일반 출력·푸시풀 설정 완료. 폴링 루프가 매 조작 뒤 입력을 읽는다고 가정합니다. C6의 충·방전은 계산하지 않고 안정된 뒤의 상태를 표시합니다.

외부 R4를 제거하는 선택은 실제 보드를 바꾸지 않는 가상 고장 실험입니다. C6은 그대로 남지만 정상 DC 바이어스를 대신하지는 못합니다.

if ((GPIOD->IDR & (1U << 4)) == 0U) {
    GPIOD->ODR &= ~(1U << 3);  // 눌림 → LOW → LED ON
} else {
    GPIOD->ODR |=  (1U << 3);  // 놓음 → HIGH → LED OFF
}

이 코드는 반복해서 확인하는 폴링(polling) 방식의 설명용 예제입니다. ODR의 읽기-수정-쓰기 경쟁은 7단원에서 다룹니다. 미정 입력을 실제 코드가 특별한 ‘?’ 값으로 읽는 것은 아닙니다. 실제로는 불안정한 0 또는 1이 읽힐 수 있어 결과를 예측할 수 없다는 표시입니다.

입력과 출력은 자동 연결되지 않습니다. 회로의 PD4 전압이 IDR에 반영되고, 프로그램이 조건문을 실행한 뒤 PD3 출력 명령을 씁니다. 내부 풀다운만 있고 스위치를 놓으면 입력은 LOW이므로, 이 단순 조건문은 버튼을 누른 것으로 해석합니다. 하드웨어 극성과 소프트웨어 판단은 반드시 맞아야 합니다.

외부 풀업 + 내부 풀다운은 ‘부동’이 아닙니다. 두 저항의 분압과 입력 임계값에 따라 전압이 결정됩니다. 이 모형은 내부 저항값·임계값을 계산하지 않으므로 ‘상충 바이어스: 판정 범위 밖’으로 표시합니다. C6의 이상 RC 시정수는 1kΩ×100nF=100μs지만, 이것만으로 모든 스위치 바운스가 제거된다고 결론지을 수는 없습니다.

확인 문제 · 내부 PUPDR=00이면 언제나 부동 입력일까요?

아닙니다. 원회로의 외부 R4가 HIGH 바이어스를 만듭니다. 외부 풀업도 제거하고 내부 풀도 없으며 스위치를 놓았을 때, 이 실습에서 부동 입력이 됩니다.

강의 기반 · 76 GPIO · 77 GPIO(2) · 76 전사 · 원회로 PDF 31쪽: PD4·R4·C6. 외부 풀 제거와 상충 풀은 추가 비교 실험입니다.

05 / 출력값과 출력 방식은 다릅니다

1을 쓰면 항상 HIGH를 밀어낼까요?

푸시풀(push-pull) 출력은 핀을 위쪽 전원 또는 아래쪽 접지로 능동 구동합니다. 오픈드레인(open-drain)은 아래쪽으로 당기는 구동만 사용합니다. 그래서 오픈드레인에서 ODR=1은 HIGH 구동이 아니라 해제(Hi-Z, 높은 임피던스)입니다. 외부 회로가 핀 전압을 정하게 됩니다.

OTYPER는 이 출력단 형태를 정하고, PUPDR는 약한 내부 풀업·풀다운을 정합니다. 두 설정은 별개입니다. OSPEEDR는 LOW↔HIGH로 전환하는 출력 에지의 특성에 관여합니다. 프로그램이 언제 토글 명령을 쓰는지를 정하는 타이머나 CPU 주파수 설정은 아닙니다.

EXPERIMENT 05출력단 경로 / 개념 파형

해 보기: ODR=1에서 푸시풀→오픈드레인을 바꾸고, ODR=0도 비교하세요. OSPEEDR 네 값을 바꿔 보세요. 예상 관찰: 오픈드레인의 1은 위·아래 구동을 모두 놓고, 파형은 에지만 달라지며 명령 시점 간격은 같습니다.

일반 출력 모드, 내부 풀 없음, 같은 LED 부하를 가정합니다. 외부 저항성 풀업이 없는 오픈드레인 해제 상태의 정확한 핀 전압은 이 모형에서 정하지 않습니다.

별도 비교: 같은 푸시풀 부하에서 OSPEEDR만 바꾼다면

해제는 논리 HIGH와 같은 말이 아닙니다. 오픈드레인 출력을 디지털 신호선으로 쓰려면 보통 적절한 풀업 경로가 필요합니다. 위 LED 회로는 LED·저항이 전원 쪽에 있지만 이상적인 저항성 풀업으로 간주하지 않습니다. 오픈드레인 해제 시 LED를 통해 접지로 돌아오는 경로가 없어 LED는 꺼지며, 핀 전압은 별도 회로 해석이 필요합니다.

파형 읽는 법: 아래 비교 파형은 선택한 출력단의 실제 측정 파형이 아니라, 동일한 푸시풀·부하 조건의 OSPEEDR 정성 비교입니다. 속도를 높이면 에지가 급해질 수 있지만 실제 전환 시간·노이즈·전류는 전원과 부하에 따라 달라집니다. 수치나 최대 주파수를 이 그림에서 읽을 수 없습니다.

확인 문제 · OSPEEDR를 Very high로 바꾸면 LED 토글 코드가 더 자주 실행될까요?

아닙니다. 토글 주기는 코드 실행, 타이머, 지연 설정 등이 정합니다. OSPEEDR는 주어진 토글 명령 이후 핀의 전환 특성에 영향을 줄 수 있습니다.

강의 기반 · 72 GPIO: OTYPER·OSPEEDR · PDF GPIO 출력 구조. 강의의 속도 수치를 모든 전원·부하 조건에 일반화하지 않습니다.

06 / 레지스터에도 주소가 있습니다

C의 한 줄은 어떤 칸을 가리킬까요?

MCU는 주변장치 레지스터를 정해진 메모리 주소에 배치합니다. 포트의 시작인 베이스 주소에 레지스터별 거리인 오프셋(offset)을 더하면 해당 레지스터 주소가 됩니다. GPIOD의 베이스는 0x40020C00입니다.

포인터(pointer)는 주소를 담는 C 변수이며, 그 주소의 내용을 읽거나 쓸 때 사용합니다. volatile은 해당 접근을 컴파일러가 일반 변수처럼 임의로 생략·합치지 않도록 표현하는 데 쓰입니다. 하드웨어 상태는 프로그램 외부에서도 바뀔 수 있기 때문입니다. 실무에서는 숫자 주소를 직접 적기보다 CMSIS의 GPIOD->IDR 같은 정의를 사용하는 편이 명확합니다.

EXPERIMENT 06메모리 맵 탐색

해 보기: IDR → ODR → BSRR를 선택하세요. 예상 관찰: 베이스는 같지만 오프셋과 접근 의미가 바뀝니다.

주소는 STM32F767 GPIOD 기준입니다. 다른 MCU 계열·포트에 그대로 복사하지 마세요. BSRR는 읽어서 상태를 확인하는 칸이 아니라 쓰기 명령이며 현재 출력 래치는 ODR에서 확인합니다.

volatile은 만능 보호 장치가 아닙니다. 여러 명령으로 이루어진 읽기-수정-쓰기를 한 번의 원자적 작업으로 만들지 않습니다. 두 실행 흐름 사이의 동기화나 전기적 정격도 보장하지 않습니다. 다음 단원에서는 ‘읽은 뒤 쓰기 전에 다른 코드가 바꿨다면?’을 직접 재현합니다.

확인 문제 · IDR과 ODR이 같은 GPIO 포트인데 주소가 다른 이유는?

서로 다른 기능의 레지스터이기 때문입니다. GPIOD IDR은 베이스+0x10=0x40020C10, ODR은 베이스+0x14=0x40020C14입니다. 입력 상태와 출력 명령을 서로 다른 칸에서 다룹니다.

강의 기반 · 74 메모리 맵 · 75 포인터 · 75 원본 주소·포인터 캡처. 원문에 인용된 RM0385와 구분하여 F767 CMSIS 정의 및 RM0410 GPIO 메모리 맵을 기준으로 합니다.
