07 / 읽는 순간과 쓰는 순간 사이

다른 핀의 변경이 왜 사라졌을까요?

ODR |= mask는 C 코드 한 줄이지만 보통 읽기 → 계산 → 쓰기로 이루어집니다. 그 사이 인터럽트 코드가 같은 ODR의 다른 비트를 바꾸면, 먼저 읽어둔 옛 값으로 덮어쓸 수 있습니다. 이렇게 실행 순서에 따라 결과가 달라지는 상황을 경쟁 조건(race condition)이라고 합니다.

BSRR(Bit Set/Reset Register)는 대상 비트를 1 또는 0으로 만드는 명령을 한 번에 쓰는 레지스터입니다. 하위 bits [15:0]은 set, 상위 bits [31:16]은 reset입니다. 따라서 PD3은 BS3(bit 3)로 1, BR3(bit 19)로 0이 됩니다. 현재 상태는 ODR에 있고, BSRR 쓰기값은 명령입니다.

EXPERIMENT 07추가 심화 · 단계별 경쟁 재현

해 보기: ODR 방식에서 ① 읽기 → ② 다른 코드의 PD4 set → ③ 메인 PD3 set 순서로 진행하세요. BSRR 방식으로 바꿔 반복합니다. 예상 관찰: ODR은 PD4 변경을 잃지만 BSRR는 보존합니다.

    이 실험의 PD4는 다른 출력 비트를 대표합니다. 4단원의 버튼 입력 회로와 별개인 동시성 예제입니다. BSRR에서는 ① 읽기가 필요 없으며 비교용 대기 지점만 보여 줍니다.

    최근 BSRR 명령: 없음

    원자적(atomic)이라는 말은 이 set/reset 쓰기가 다른 핀의 ODR 값을 읽어 되쓰는 중간 단계를 요구하지 않는다는 뜻입니다. 같은 핀을 두 코드가 반대로 제어하면 마지막 명령에 따라 결과가 달라집니다. BSRR도 의도 충돌 자체를 해결해 주지는 않습니다. 또한 ODR을 읽고 반전할 값을 결정하는 ‘토글’ 전체가 자동으로 원자적이 되는 것은 아닙니다.

    확인 문제 · PD3를 LOW로 만드는 BSRR 쓰기값은?

    1U << (3+16), 즉 0x00080000입니다. BR3 명령만 쓰므로 다른 ODR 비트는 유지됩니다. 이 UI는 동일 핀에 set/reset을 동시에 요청하지 않습니다.

    08 / 버튼의 변화가 CPU에 닿기까지

    입력이 바뀌면, 누가 처리할까요?

    폴링은 프로그램이 입력을 반복해서 확인하는 방식입니다. 인터럽트(interrupt)는 사건이 발생했을 때 CPU가 처리 루틴을 실행하도록 요청하는 방식입니다. 그 처리 루틴을 ISR(Interrupt Service Routine)이라고 합니다. ‘즉시 처리’라고 부르기도 하지만 실제 지연은 우선순위와 마스킹 등에 따라 달라집니다.

    에지(edge)는 논리값이 바뀌는 순간입니다. 버튼을 누르면 HIGH→LOW인 하강 에지, 놓으면 LOW→HIGH인 상승 에지입니다. SYSCFG는 EXTI4에 어느 포트의 4번 핀을 연결할지 선택합니다. EXTI는 선택한 에지를 감지하여 pending(처리 대기 표시)을 남깁니다. IMR는 인터럽트 전달 마스크, NVIC는 CPU 쪽 인터럽트 제어기입니다.

    EXPERIMENT 08에지 감지와 전달을 분리하기

    해 보기: ① SYSCFG 클럭 켜기 → 소스를 PD4로 선택 → ② 버튼 누르기. IMR·NVIC가 꺼져 있어도 pending이 생깁니다. ③ 두 전달 허용을 켜고 ISR 진입 → PR 지우기 → 복귀. 예상 관찰: pending을 지우지 않고 복귀하면 재진입이 가능합니다.

    전제: PD4는 입력, 외부 풀업 연결, Port D 클럭 ON입니다. 교육용 단일 EXTI4 단계 모델이며 NVIC의 별도 pending 래치·우선순위·선점·실제 시간은 생략합니다.

    SYSCFG 클럭을 끄더라도 이미 선택한 라우팅은 유지됩니다. IMR/NVIC를 끄는 것과 EXTI pending을 지우는 것도 별개의 조작입니다. 버튼을 같은 상태로 유지하면 새 에지는 생기지 않습니다.

    pending은 ‘0을 써서’ 지우는 비트가 아닙니다.

    EXTI_PR은 W1C(Write One to Clear), 즉 지울 자리에 1을 쓰는 규칙입니다. EXTI->PR = (1U << 4);처럼 직접 씁니다. PR |= mask는 다른 pending 비트까지 읽어 1로 되쓸 수 있어, 처리하지 않은 사건까지 지울 수 있습니다. pending을 clear하는 것은 전달을 허용하는 준비가 아니라 기록된 사건을 처리·정리하는 동작입니다.

    // 설명용 핵심 설정: 실제 보드 초기화 전체는 아닙니다.
RCC->APB2ENR |= (1U << 14);       // SYSCFGEN
SYSCFG->EXTICR[1] = (SYSCFG->EXTICR[1] & ~0xFU) | 3U; // PD4
EXTI->FTSR |= (1U << 4);          // 하강 에지
EXTI->PR = (1U << 4);             // 시작 전 남은 사건 정리
EXTI->IMR |= (1U << 4);
NVIC_EnableIRQ(EXTI4_IRQn);

void EXTI4_IRQHandler(void) {
    if (EXTI->PR & (1U << 4)) {
        EXTI->PR = (1U << 4);     // 처리한 EXTI4만 W1C
        /* 짧게 상태 기록 후 복귀, 긴 작업은 메인 루프에서 */
    }
}

    추가 심화: 스위치 바운스와 디바운스. 실제 접점은 한 번 눌러도 짧게 여러 번 튈 수 있어 여러 에지가 생깁니다. 이 모형의 버튼은 깨끗한 에지 한 번입니다. 안정된 상태를 일정 시간 확인하는 디바운스 등은 실제 부품과 요구 응답시간에 맞춰 설계해야 합니다. ISR 안에 긴 delay를 넣어 해결하려 하면 다른 처리까지 지연될 수 있습니다.

    확인 문제 · IMR[4]=0일 때 발생한 하강 에지는 반드시 잊힐까요?

    아닙니다. PD4가 EXTI4 소스로 연결되고 하강 에지 감지가 켜져 있으면 pending을 기록할 수 있습니다. IMR은 CPU 방향 전달을 막는 것이며 에지 감지·pending 기록 자체와 다릅니다. 다시 전달을 허용하기 전에 남은 pending을 어떻게 처리할지 생각해야 합니다.

    09 / 실제 보드 개정으로 마무리

    PD3 코드를 PC6 보드에서 실행한다면?

    LED 핀 변경은 소프트웨어 이름만의 문제가 아닙니다. 하드웨어 변경 공지는 PD3→PC6을 명시합니다. 핀 번호뿐 아니라 포트 클럭, 레지스터 이름, 2비트 모드 필드, ODR·BSRR 비트가 함께 달라집니다. PD4 버튼은 그대로여도 LED 초기화는 새 회로에 맞아야 합니다.

    해 보기: 개정 PC6 보드에 구형 PD3 코드가 선택되어 있습니다. 각 항목을 바꾸며 원인을 지우세요. 예상 관찰: 코드 포트·클럭·핀·모드·출력값을 모두 맞추면 LED ON 목표가 충족됩니다.

      이것은 리셋 이후 적용할 초기화 설정을 비교하는 과제입니다. 선택을 바꾸면 새로운 설정안으로 다시 판정하며, 앞에서 설정했던 핀의 상태를 계속 누적하지 않습니다. 잘못된 포트/모드에서는 실제 LED 상태를 단정하지 않고 목표 미달로 표시합니다.

      디버깅의 순서: 먼저 회로에서 LED net이 어느 핀으로 가는지 확인합니다. 그 포트의 클럭, MODER 필드, 출력 타입, 출력값을 차례로 읽습니다. 소프트웨어의 0/1과 LED의 켜짐/꺼짐을 연결할 때는 능동 LOW 배선도 다시 확인합니다. 강의 화면과 내 보드가 다르면 코드보다 먼저 보드 개정을 확인하는 습관이 도움이 됩니다.

      최종 확인 · PC6 LED를 LOW로 만드는 설정을 말로 설명해 보세요.

      GPIOC 클럭을 켜고, GPIOC MODER의 [13:12]를 01로 설정합니다. 푸시풀 출력이라면 ODR bit6에 0을 쓰거나 BSRR bit22로 reset 명령을 보냅니다. +3.3V→LED→330Ω→PC6→접지의 전류 경로가 생겨 켜집니다. 버튼 PD4 입력을 함께 사용한다면 Port D 클럭과 입력 설정도 별도로 필요합니다.
